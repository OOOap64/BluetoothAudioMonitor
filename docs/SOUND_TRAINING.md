# Обучение модели звуков

Приложение умеет определять не только речь, но и другие события: крик,
пение птиц, открывание двери, треск огня, музыку, шум и любые ваши классы.
Для этого используется собственная модель.

## Готовая модель

В комплекте уже лежит `models/sound_model.npz`. Она обучена на ESC-50 и
RAVDESS и различает классы `speech`, `yelling`, `bird_singing`,
`door_opening`, `fire_burning`, `noise`. Точность на отложенной проверке —
85,1%, отчёт с метриками и матрицей ошибок: `models/sound_model_report.json`.
Кнопки обучения в интерфейсе нет: модель подхватывается автоматически, а
переобучение выполняется из командной строки по инструкции ниже.

ESC-50 распространяется по лицензии CC BY-NC 3.0, RAVDESS — CC BY-NC-SA 4.0.
Используйте полученную модель с учётом этих ограничений (в частности,
некоммерческое использование). Подробнее — `models/README.md`.

## 1. Подготовьте датасет

Создайте папку `data/sound_dataset` (или любую другую) и подкаталоги —
по одному на класс. Имя подкаталога становится названием класса.

```
data/sound_dataset/
├── speech/
│   ├── 0001.wav
│   └── ...
├── yelling/
├── bird_singing/
├── door_opening/
├── fire_burning/
├── music/
└── noise/
```

Требования к данным:

- Форматы: WAV, FLAC, OGG/Opus, AIFF (через soundfile); MP3/M4A/AAC/WMA и
  видео с аудиодорожкой — если установлен PyAV.
- Один файл — одно событие, желательно 1–10 секунд.
- Минимум 2 класса и хотя бы по 2–10 файлов для проверки работы. Для
  реального качества стремитесь к 100–1000 примерам на класс.
- Балансируйте классы. Сильный дисбаланс частично компенсируется весами,
  но лучше иметь сопоставимое число примеров.
- Записывайте разные условия: разные микрофоны, расстояния, громкость,
  фоновый шум. Модель должна слышать не только ваш голос из одной комнаты.
- Не подписывайте шум как целевой класс. Для фона создайте отдельный класс
  `noise` или `other`.

## 2. Обучите модель

В интерфейсе кнопки обучения нет. Обучение и переобучение выполняются из
командной строки:

```bash
python tools/train_sound_model.py \
  --dataset data/sound_dataset \
  --output models/sound_model.npz \
  --epochs 300
```

Полезные параметры:

| Параметр | Значение |
|---|---|
| `--epochs` | число эпох (по умолчанию 300) |
| `--learning-rate` | шаг обучения (0.02) |
| `--l2` | регуляризация (1e-4) |
| `--val-split` | доля проверки (0.2) |
| `--max-per-class` | ограничить число файлов на класс |
| `--no-augment` | отключить усиление данных |
| `--report` | сохранить отчёт в JSON |
| `--list-classes` | только показать классы и выйти |

Скрипт печатает точность и precision/recall/f1 по каждому классу. Если
точность на проверке низкая, добавьте данные, уменьшите число классов или
проверьте, нет ли ошибок в разметке.

## 3. Как это работает

1. Аудио приводится к моно, 16 кГц (при необходимости), обрезается до
   10 секунд из середины записи.
2. Считаются мел-спектрограмма (64 фильтра), MFCC (20 коэффициентов),
   дельты и спектральные статистики (центр, ширина, rolloff, flatness,
   ZCR, RMS).
3. Признаки стандартизуются и подаются в многоклассовую логистическую
   регрессию с Adam, L2-регуляризацией и весами классов.
4. Лучшая эпоха выбирается по проверочной выборке и сохраняется в
   `models/sound_model.npz` вместе с метаданными и матрицей ошибок.

Модель лёгкая (десятки килобайт), работает на CPU и не требует GPU.
Для ещё большей точности можно заменить признаки на эмбеддинги AST/YAMNet
или дообучить AST, но это требует PyTorch/GPU и сотен примеров на класс.

## 4. Проверка

В приложении выберите источник звука и запустите захват. В блоке
«Определение источника звука (ИИ)» появятся результаты своей модели
(`source: custom`) и AudioSet (`source: audioset`), а также категория.

Быстрая проверка из Python:

```python
from src.custom_sound_model import CustomSoundModel
from src.custom_sound_model import load_audio

model = CustomSoundModel('models/sound_model.npz')
audio, rate = load_audio('data/sound_dataset/yelling/test.wav')
for item in model.predict_proba(audio, rate)[:3]:
    print(item['label'], round(item['score'], 3))
```

## 5. Откуда брать данные

- **ESC-50** — 50 классов бытовых/природных звуков, 2000 клипов по 5 с.
- **UrbanSound8K** — городские звуки: сирены, дрель, собаки, дети.
- **FSD50K** — 200+ классов AudioSet, удобно для редких событий.
- **AudioSet** — огромный набор, но требует фильтрации и разметки.
- **VocalSound** — крики, смех, плач, кашель, вдохи.
- **BirdCLEF** — пение птиц.
- Собственные записи: телефон/микрофон, обязательно с разнообразными
  условиями и отрицательными примерами (`noise`, `speech`, `music`).

Соблюдайте лицензии датасетов. Не используйте записи людей без согласия.

## 6. Частые проблемы

**«Нужно минимум два класса»** — создайте хотя бы два подкаталога с аудио.

**Низкая точность** — добавьте примеры, особенно похожих классов
(`speech` vs `yelling`, `door` vs `knock`), проверьте разметку, увеличьте
`--epochs`, попробуйте больше данных и аугментацию.

**Все предсказания — один класс** — сильный дисбаланс или слишком мало
данных. Уравняйте классы, добавьте `noise`/`other`.

**Ошибка чтения MP3/M4A** — установите `av` (`pip install av`) или
конвертируйте файлы в WAV/FLAC.

**Модель не подхватилась** — проверьте путь `models/sound_model.npz` или
задайте `BLUETOOTH_MONITOR_SOUND_MODEL`. Перезапустите захват (F4/F3),
если модель менялась во время работы.

**Микрофон не записывается** — проверьте `sounddevice`, PortAudio и
разрешение на микрофон. Сеанс всё равно сохранится с ошибкой в поле
`recording`.
