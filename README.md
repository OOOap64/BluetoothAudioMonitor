# Bluetooth Audio Monitor

Программа для анализа аудио с Bluetooth-устройств, микрофона или системного
звука (WASAPI loopback). Показывает характеристики сигнала, определяет источник
звука нейросетью и распознаёт речь в текст.

## Возможности

- **Сканирование Bluetooth устройств**: наушники, гарнитуры, колонки, TWS.
- **Захват системного звука (WASAPI loopback)**: слышит то, что играет на
  динамиках/наушниках, включая Bluetooth-аудио.
- **Захват с микрофона или любого устройства ввода**: выбор источника в списке.
- **Анализ аудиофайлов**: WAV, MP3, FLAC, OGG/Opus, M4A/AAC, WMA, AIFF и
  видеофайлы с аудиодорожкой.
- **Сохранение проанализированного звука**: кнопка «💾 Сохранить запись аудио»
  или клавиша F11 во время захвата записывает буфер последних ~30 секунд в WAV.
- **Распознавание речи**: faster-whisper (русский, английский, автоопределение), выбор модели Tiny/Base/Small/Medium прямо в интерфейсе. По умолчанию Tiny: частичный текст появляется каждые 0.5 с, полная фраза — через 0.2 с после паузы.
- **Автокорректировка речи**: исправление типичных ошибок распознавания, пробелов, пунктуации и регистра.
- **Озвучивание текста (TTS)**: системные голоса Windows, Edge TTS и локальные модели Piper, включая собственный обученный голос.
- **Чтение произвольного текста**: поле «Свой текст», кнопка/F9, автоматическое или ручное сохранение результата в журнал (F10).
- **Журнал сеансов**: распознанный/прочитанный текст, голос, микрофон и динамик, язык, координаты, состояние аудио и пути к WAV-записям. Экспорт в CSV/JSON.
- **Запись микрофона во время чтения** и сохранение синтезированного аудио TTS.
- **Своя модель звуков**: в комплекте уже обученная модель для классов «речь», «крик», «птицы», «дверь», «огонь», «шум»; при необходимости её можно переобучить из командной строки.
- **Определение источника звука**: собственная обученная модель + модель AudioSet (AST).
- **Стресс-тест озвучивания**: тысячи последовательных чтений с фиксацией первого сбоя.
- **Характеристики звука в текстовом виде**: их можно скопировать одной кнопкой.

## Отображаемые характеристики

- Частота дискретизации, количество каналов, формат
- Длительность записи
- RMS (уровень громкости), пиковый уровень, средняя амплитуда
- Уровень сигнала в dBFS и индикатор уровня
- Спектральный центр и доминирующая частота
- Пик-фактор (crest factor)
- Распределение энергии по диапазонам: суб-бас, бас, середина,
  верхняя середина, высокие частоты
- Распознанный текст с отметками времени (для файлов)

## Требования

- Python 3.10+ (проверено на 3.14)
- Windows 10/11 (loopback работает на Windows; на Linux/macOS доступен
  захват с устройств ввода)
- Микрофон или аудиовыход
- Bluetooth адаптер (для сканирования)

## Установка

```bash
python -m venv venv
venv\Scripts\activate        # Windows
# source venv/bin/activate   # Linux/macOS
pip install -r requirements.txt
```

Для системного звука на Windows используется пакет `soundcard`; он уже включён
в `requirements.txt`. Для запуска тестов установите `pytest`:

```bash
pip install pytest
python -m pytest -q
```

Быстрый цикл отладки без стресс-тестов, обучения моделей и GUI:

```bash
python -m pytest -q -m "not slow and not training and not gui"
```

Полный прогон: `python -m pytest -q`. Отдельно: `-m gui`, `-m slow`,
`-m training`. Медленные тесты больше не запускаются при каждом изменении.

Чтобы повторные неудачные попытки скачивания модели не замедляли отладку,
можно включить офлайн-режим после прогрева кэша Hugging Face:

```powershell
$env:HF_HUB_OFFLINE = "1"
$env:TRANSFORMERS_OFFLINE = "1"
```

Точность не меняется: используются те же веса, модель, `beam_size`, VAD и
промпты.

## Использование

1. Нажмите «Сканировать» (F2) для поиска Bluetooth-устройств (необязательно).
2. Выберите источник аудио:
   - «Авто» — сначала пробует системный звук (loopback динамика по умолчанию),
     затем микрофон;
   - `[WASAPI LOOPBACK] ...` — захват системного звука;
   - `[ВХОД] ...` — микрофон или линейный вход.
 3. Выберите язык речи (по умолчанию русский) и модель распознавания
    (по умолчанию Tiny — минимальная задержка; Base/Small/Medium точнее, но медленнее).
4. Нажмите «Начать захват и анализ» (F3).
5. Чтобы сохранить проанализированный звук в WAV, нажмите «💾 Сохранить запись аудио» (F11). Кнопка и клавиша работают во время захвата: сохраняется буфер последних ~30 секунд.
6. Для анализа готовой записи нажмите «Загрузить аудиофайл...» (Ctrl+O).
7. Кнопка «Скопировать характеристики в текст» (Ctrl+Shift+C) помещает отчёт в буфер обмена.
8. Для озвучивания используйте блок «3. Озвучивание речи (TTS)»: выберите голос, нажмите «▶ Проверить» (F8) для примера, затем «🔊 Озвучить текст» (F5). «Проверить» произносит текст из поля «Свой текст», если он введён, иначе короткий пример на языке голоса. Кнопка «⏹ Стоп» (Esc) останавливает чтение, «Последний фрагмент» (F7) читает последнюю строку.
9. Кнопка «➕ Добавить голос...» (Ctrl+I) открывает единый список системных голосов, Edge TTS и локальных голосов Piper. После добавления голос сразу выбирается и звучит пример.
10. Флажок «Автокоррекция речи» исправляет типичные ошибки распознавания; для уже показанного текста есть кнопка «✍ Исправить текст» (F6).
11. Для чтения любого своего текста используйте блок «4. Свой текст»: введите текст, при необходимости укажите широту/долготу (или нажмите «📍 Определить»), включите «Записывать микрофон во время чтения» и нажмите «🔊 Прочитать» (F9). Если выбран английский голос, а текст содержит кириллицу, приложение автоматически использует русский голос и пишет об этом в журнал.
12. Результат каждого чтения сохраняется автоматически (флажок «Автосохранение») либо кнопкой «💾 Сохранить» (F10). В журнал попадают текст, распознанная речь, голос, микрофон, динамик, язык, координаты, состояние аудио, путь к записи микрофона и путь к аудио TTS.
13. Кнопка «📂 Журнал» (Ctrl+L) открывает таблицу сеансов с экспортом в CSV/JSON.
14. Модель звуков уже обучена и подхватывается автоматически. Кнопки обучения в интерфейсе нет; переобучение на своём датасете выполняется из командной строки (см. раздел «Обучение модели звуков»).

### Журнал чтения и координаты

Журнал хранится в `data/read_aloud/sessions.jsonl` (каталог можно изменить
переменной `BLUETOOTH_MONITOR_DATA_DIR`). Рядом лежат `recordings/` (WAV с
микрофона) и `tts/` (синтезированное аудио).

Координаты можно:

- ввести вручную в полях «Широта»/«Долгота» — они сохраняются с источником
  `manual`;
- определить кнопкой «📍 Определить» по IP (ipapi.co, резервный ip-api.com);
- задать переменными `BLUETOOTH_MONITOR_LATITUDE` и
  `BLUETOOTH_MONITOR_LONGITUDE` (приоритет выше кеша);
- взять из кеша `data/location.json` (обновляется кнопкой определения).

Сетевой запрос выполняется только по кнопке, поэтому сохранение сеанса не
зависает без интернета. Если координат нет, поле `location` остаётся пустым.

Запись журнала содержит: `text`, `recognized_text`, `voice` (имя, движок),
`devices` (микрофон и динамик), `language`, `location` (lat/lon/источник),
`audio.status`, `audio.duration_seconds`, `recording` (путь и параметры WAV),
`tts_audio`, `error`, `created_at`.

### Обучение модели звуков

В комплекте уже есть модель `models/sound_model.npz`, обученная на открытых
записях ESC-50 и RAVDESS. Она различает шесть классов: `speech`, `yelling`,
`bird_singing`, `door_opening`, `fire_burning`, `noise`. Точность на
отложенной проверке — 85,1% (подробный отчёт:
`models/sound_model_report.json`). Это базовая модель; для ваших условий,
микрофона и языка лучше обучить свою.

Кнопки обучения в интерфейсе нет — обучение выполняется из командной
строки. Модель обучается на папках: имя папки — класс, внутри аудиофайлы.

```
data/sound_dataset/
├── speech/            # речь
├── yelling/           # крик, плач, громкие возгласы
├── bird_singing/      # пение птиц
├── door_opening/      # дверь, стук, скрип
├── fire_burning/      # огонь, треск, взрыв
├── music/             # музыка
└── noise/             # шум, ветер, фон
```

Чем больше примеров на класс (желательно от 100) и чем разнообразнее
записи, тем лучше. Переобучение из командной строки:

```bash
python tools/train_sound_model.py \
  --dataset data/sound_dataset \
  --output models/sound_model.npz \
  --epochs 300
```

Модель использует MFCC/спектральные признаки и многоклассовую логистическую
регрессию, поэтому обучается на CPU: секунды на небольшом наборе, минуты на
тысячах записей. Файл сохраняется по пути
`models/sound_model.npz` и подхватывается автоматически (или берётся из пути
`BLUETOOTH_MONITOR_SOUND_MODEL`). Если модели нет, используется AudioSet/AST.
Названия классов AudioSet дополнительно сворачиваются в категории: `speech`,
`yelling`, `bird_singing`, `door`, `fire_burning`, `alarm`, `music`,
`animal`, `water`, `traffic`, `applause`, `noise`.

Где брать данные: ESC-50 и UrbanSound8K (бытовые/городские звуки), FSD50K и
AudioSet (широкий набор событий), VocalSound (крики/вокализации), RAVDESS
(эмоциональная речь), BirdCLEF (птицы). Собственные записи с телефона тоже
подходят — главное, чтобы посторонние шумы не были подписаны как целевой
класс. Включённая модель использует ESC-50 (CC BY-NC 3.0) и RAVDESS
(CC BY-NC-SA 4.0), подробности и условия — в `models/README.md` и
`docs/SOUND_TRAINING.md`.

### Стресс-тест чтения вслух

Проверка тысяч последовательных чтений без звуковой карты:

```bash
python tools/stress_read_aloud.py --iterations 2000 --verbose
```

Проверка обработки сбоя (искусственная ошибка на 42-й итерации):

```bash
python tools/stress_read_aloud.py --iterations 100 --fail-at 42
```

С реальным TTS:

```bash
python tools/stress_read_aloud.py --iterations 20 --backend tts
```

Скрипт останавливается на первом сбое, печатает трассировку и сохраняет
журнал во временный каталог. Тесты `pytest` включают 500 последовательных и
160 параллельных чтений, а также очередь из 2000 вызовов TTS.

### Piper (локальное озвучивание)

Piper уже установлен в папку `piper` проекта вместе с русскими голосами
Ирина, Дмитрий и Денис. Он работает офлайн и выбирается по умолчанию, если
пользователь ещё не выбрал другой голос.

Piper 1.2.0 не умеет работать с путями, содержащими кириллицу (например,
`C:\Users\Пользователь\...`), и завершается с кодом `0xC0000409`. Приложение
автоматически копирует рантайм Piper во временный ASCII-каталог
(`%PUBLIC%\BluetoothAudioMonitor` или `%TEMP%\BluetoothAudioMonitor`) и
передаёт ему только ASCII-пути. При необходимости каталог можно задать
переменной `BLUETOOTH_MONITOR_ASCII_DIR`.

Чтобы добавить новый голос, положите файлы `голос.onnx` и `голос.onnx.json`
в `piper\voices` — голос появится в списке автоматически. Нестандартные пути
можно задать переменными окружения `BLUETOOTH_MONITOR_PIPER_DIR`,
`BLUETOOTH_MONITOR_PIPER_EXE` и `BLUETOOTH_MONITOR_PIPER_VOICES`.

При первом запуске модели скачиваются с Hugging Face, поэтому запуск может
занять несколько минут. Дальше они берутся из локального кеша.

## Решение проблем

**`property 'hostapi' of 'default' object has no setter`** — больше не
возникает: приложение не меняет глобальный host API, а открывает нужное
устройство напрямую.

**`WasapiSettings.__init__() got an unexpected keyword argument 'loopback'`** —
в установленной версии `sounddevice` нет loopback-режима. Теперь системный звук
захватывается через `soundcard` (WASAPI loopback), поэтому эта ошибка исчезла.

**Loopback-устройства не найдены** — проверьте, что установлен `soundcard`
(`pip install soundcard`) и что в Windows есть активное устройство
воспроизведения. Приложение при этом продолжит работать с микрофоном.

**Речь плохо распознаётся** — по умолчанию используется модель `tiny`, звук
приводится к 16 кГц, очищается от постоянной составляющей и гула ниже 80 Гц и
нормализуется. Не меняйте модель сразу: сначала добавьте конкретные фразы в
поле «Частые фразы — подсказки распознавания» в блоке захвата. Они передаются
Whisper как `initial_prompt` и `hotwords`, повышают точность нужных команд и
почти не увеличивают задержку. По умолчанию там уже есть примеры фраз; список
сохраняется в настройках и применяется и к живому захвату, и к анализу файла.
Только если подсказок мало, выберите `Base` (точнее `Tiny`), затем `Small` или
`Medium` — live-задержка при этом растёт до 2 с и более. Выбор из интерфейса
имеет приоритет над переменной `BLUETOOTH_MONITOR_WHISPER_MODEL`.

Подсказки можно задать и без GUI — в файле `data/asr_phrases.txt` (одна фраза
на строку) или переменными окружения:

```powershell
$env:BLUETOOTH_MONITOR_PHRASES_FILE="C:\path\to\phrases.txt"
# либо сразу:
$env:BLUETOOTH_MONITOR_PHRASES="Открой окно и включи свет`nПривет, меня зовут"
```

**Модель не загружается** — нужен доступ к Hugging Face при первом запуске
(модель `small` занимает около 460 МБ). Если сети нет, положите модель в кеш
заранее или задайте `BLUETOOTH_MONITOR_WHISPER_MODEL=base`; при недоступности
выбранной модели приложение само откатывается на `base`. Скорость и точность
можно настроить переменными `BLUETOOTH_MONITOR_WHISPER_BEAM` (по умолчанию 1) и
`BLUETOOTH_MONITOR_WHISPER_FALLBACK`.

**После выбора голоса текст читается другим голосом** — нажмите «▶ Проверить» рядом со списком. Выбор сохраняется в настройках; если движок не может применить голос, в журнале появится сообщение об ошибке. Для локального чтения выберите голос Piper.

**Нет звука Edge TTS** — Edge TTS создаёт MP3. Приложение проигрывает его через Windows MCI, поэтому `pygame` не обязателен. Проверьте громкость и устройство вывода Windows.

**Озвучка молчит, хотя в журнале нет ошибок** — Piper, Edge TTS и pyttsx3 играют через устройство вывода Windows по умолчанию. Проверьте «Параметры → Система → Звук»: должны быть выбраны нужные динамики/наушники, громкость не равна нулю, нет монопольного захвата устройства другим приложением. Нажмите «▶ Проверить» рядом со списком голосов: если слышно пример, выбранный голос работает. Системные голоса Windows (SAPI/pyttsx3) запускаются в главном потоке GUI — в фоновом потоке они блокируются и не дают звука.

## Технические детали

- **GUI**: PyQt6
- **Захват**: soundcard (WASAPI loopback) + sounddevice/PortAudio (микрофоны)
- **Распознавание речи**: faster-whisper (по умолчанию `tiny`, int8 на CPU), beam=1, до 8 потоков CPU, вход 16 кГц, фильтрация гула и нормализация; частичные окна 1 с каждые 0.5 с, финальная фраза после паузы 0.2 с
- **Настройка задержки и точности**: `BLUETOOTH_MONITOR_WHISPER_MODEL`, `BLUETOOTH_MONITOR_WHISPER_BEAM`, `BLUETOOTH_MONITOR_WHISPER_THREADS`, `BLUETOOTH_MONITOR_PHRASES`, `BLUETOOTH_MONITOR_PHRASES_FILE`
- **Классификация**: transformers + AST (AudioSet)
- **Анализ**: FFT/спектр, dBFS, энергия по диапазонам
- **Файлы**: PyAV (FFmpeg) с резервным декодером soundfile
